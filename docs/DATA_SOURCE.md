# 真实数据接入说明（扶摇 · 同花顺金融数据API）

本文件记录真实数据源的接入方式、**实测发现的上游不一致**，以及由此产生的工程处理。
所有结论都来自实际调用，不是照抄文档。

---

## 1. 一句话结论

接入扶摇后，产品**第一次遇到了真实上游的"脏"**：披露日系统性错位、字段名与文档不符、
文档列出的路由返回 404、部分能力根本不存在。

这些不是接不接的问题，而是**产品有没有能力识别并如实标注**的问题。
本适配层的设计目标就是：**把上游的不可信之处挡在产品之外，并且留下证据。**

---

## 2. 运行方式

```bash
# ① 配置密钥（.env 已被 .gitignore 排除，绝不入仓）
cp .env.example .env
# 编辑 .env：FUYAO_API_KEY=<你的 Key>

# ② 拉取并落盘（带本地缓存，重复执行不会重复打上游）
npm run fetch:fuyao              # 有缓存则用缓存
npm run fetch:fuyao:refresh      # 忽略缓存，重新拉取

# ③ 用真实数据跑复盘
npm run analyze -- --source real --out docs/samples/real
npm start                        # 页面上切换「数据源」下拉即可
```

### 为什么落盘而不是运行时直连

| 原因 | 说明 |
| --- | --- |
| 密钥不出现在产物里 | 落盘快照**不含任何密钥**，因此 `data/real/` 可以安全入库，评审无需申请 Key 也能看到真实数据的报告 |
| 报告可复现 | 结果不依赖"上游此刻是否可用"，也不受上游后续修订影响 |
| 不打扰上游 | 页面每次刷新都打接口既没必要，也容易触发限流 |

落盘产物：`data/real/{market,decisions,events,meta}.json`（约 1.2 MB，2 749 个数据点，24 条序列）。

## 3. 字段映射

扶摇只提供一部分字段。**能映射的映射，不能映射的一律不出点**，交给产品的数据质量层报缺口 ——
不补零、不用代理指标冒充。

| 内部序列 | 来源 | 口径 | 可得时点 |
| --- | --- | --- | --- |
| `price:<symbol>` | `/api/a-share/prices/historical` | 未复权日收盘价，CNY/股 | 当日 15:00 |
| `index:000300.SH` | 同上（指数） | 未复权指数收盘，点 | 当日 15:00 |
| `revenueYoy:<symbol>` | `/api/a-share/financials/indicators` | 营业收入同比增长率，% | 披露日（见第 4 节） |
| `netProfitYoy:<symbol>` | 同上 | 归母净利润同比增长率，% | 披露日 |
| `roe:<symbol>` | 同上 | 加权平均净资产收益率，% | 披露日 |
| `grossMargin:<symbol>` | 同上 | 销售毛利率，% | 披露日 |
| `assetsDebtRatio:<symbol>` | 同上 | 资产负债率，% | 披露日 |
| `peTtm:<symbol>` | **推导**：价格 ÷ TTM 每股收益 | 倍，周频 | 当日收盘 |
| `pb:<symbol>` | **推导**：价格 ÷ 每股净资产 | 倍，周频 | 当日收盘 |
| `dividendYield:*` | ❌ 扶摇未开放 | — | — |
| `nplRatio:*` | ❌ 扶摇财务指标不含不良贷款率 | — | — |
| `pmi:CN` | ❌ 扶摇不提供宏观数据 | — | — |

推导口径写进了 `data/real/meta.json` 的 `fieldCaliber`，页面上点开任一估值事实也能看到。

**PE / PB 为什么自己算**：扶摇没有估值接口。PE = 收盘价 ÷ TTM 每股收益，
TTM 由**累计口径的季报**拆分：`Q4 → 当年年报 EPS`；`Q1/Q2/Q3 → 上年年报 EPS + 本年累计 − 上年同期累计`。
PB = 收盘价 ÷ 每股净资产，股本由 `归母净利润 ÷ 基本每股收益` 反解（同报告期口径自洽）。

## 4. 上游不一致（实测，共 5 处）

### 4.1 披露日晚了整整一年（最严重）

`income-statements` / `balance-sheets` 返回的 `report_date_ms`，在多个标的、多个报告期上
**超出 A 股法定披露期限约一年**：

| 标的 | 报告期 | 期末 | 上游给出的披露日 | 法定最晚 | 判定 |
| --- | --- | --- | --- | --- | --- |
| 600519.SH | 2024Q1 | 2024-03-31 | 2025-04-30 | 2024-04-30 | 超期 365 天 |
| 600519.SH | 2023Q3 | 2023-09-30 | 2024-10-26 | 2023-10-31 | 超期 361 天 |
| 000001.SZ | 2024FY | 2024-12-31 | 2026-03-21 | 2025-04-30 | 超期 325 天 |
| 000001.SZ | 2023FY | 2023-12-31 | 2025-03-15 | 2024-04-30 | 超期 319 天 |
| 300750.SZ | 2025Q1 | 2025-03-31 | 2025-04-15 | 2025-04-30 | ✅ 法定期限内（正确） |

**同一批数据里既有错的也有对的** —— 所以既不能整体丢弃，也不能整体信任。
本次取数窗口（2022—2024）内 **36 个报告期的披露日无一通过校验**。

这一点对复盘产品是致命的：披露日是时点闸门唯一的依据。
若直接采信，会得出"2023 年报到 2025 年 4 月才可得"这种结论，
把当时明明已知的信息判成未知，**整个复盘的价值就没了**。

**处理方式**：按 A 股法定披露期限做合理性校验，通过则采用，不通过则**降级到法定截止日**
（一季报 4/30、半年报 8/31、三季报 10/31、年报次年 4/30，取当日 23:59:59），
并在 `meta.upstreamAnomalies` 中逐条留证（本次 36 条）。

这是**保守策略**：宁可晚一点确认，也绝不提前知道。

> 说明：约一年后的披露日之所以错，最可能是上游年份字段错位；但本适配层不去"修正"它，
> 只做**可信性判定 + 保守降级**。修正等于替上游猜，猜错的方向恰好会让产品"提前知道"。

### 4.2 财务指标 ID 与文档不一致

文档写 `operating_income_yoy_growth_ratio`，实际返回 `calculate_operating_income_yoy_growth_ratio`（多一层前缀）；
文档写 `net_profit_yoy_growth_ratio`，实际是 `calculate_parent_holder_net_profit_yoy_growth_ratio`。

**处理方式**：按**后缀匹配**，精确同名优先，找不到再退到带前缀的版本。不硬编码字段名。

### 4.3 文档列出的路由返回 404

`/api/a-share/corporate-actions`（除复权 / 分红事件）在文档接口总览中列出，
实际调用返回 `code=404 Route not found`。股息率因此**无法核验**。

### 4.4 参数含未编码中文时返回 HTML 错误页，而不是约定的信封

`/api/meta/tickers/search?q=平安银行` 返回 Tomcat 的 HTML 400 页面。
文档承诺"所有业务结果（含错误）HTTP 200 + 统一信封"，此处不是。
若客户端只看 HTTP 状态码或直接 `JSON.parse`，会得到一个难以定位的解析异常。

**处理方式**：解析前先判定响应体是否为 JSON，不是则抛 `RESPONSE_NOT_JSON` 并附上响应片段。

### 4.5 鉴权失败是 HTTP 200 + `code=2003`，不是 401

用 `Authorization: Bearer` 会得到 `{"code":2003,"message":"Missing X-api-key"}` 且 HTTP 200。
正确的头是 `X-api-key`。只看 HTTP 状态码会把鉴权失败当成成功。

## 5. 一个刻意的口径选择：为什么用未复权价

前复权价会随**每一次分红被追溯修改** —— 同一份报告今天生成和三个月后生成，数字不一样。
对一个以"可复现"为前提的复盘产品，这是致命的。

因此价格序列与成交价一律取**未复权**，理由：

1. 未复权价就是当日真实成交价，与决策记录里"我买在哪"口径一致；
2. 历史值不被后续除权追溯修改，报告可复现；
3. 未复权序列的计算不会引入浮点残值（前复权会算出 `1560.0777699999999` 这种数）。

**代价**：跨除息日的持有期收益会少一块分红。这一点写在了 `meta.fieldCaliber` 里，没有隐去。

## 6. 决策记录与真实价格的一致性

演示样本的**买入理由与离场理由是匿名样本**（非真实投资者行为），但它们是**为构造价格写的**。
直接套用真实价格会自相矛盾 —— 例如理由写"触及事前设定的止损线"，
而真实行情里该止损线从未触发（区间最低仅 −0.66%）。

**处理方式**：按离场理由的**行为含义**，从真实价格反推一个与该理由事实上相容的离场日。
规则全部可复现、写进 `meta.decisionPolicy.exitRules`，不人工指定任何日期：

| 决策 | 规则 | 参数 | 依据的原文 | 推导结果 |
| --- | --- | --- | --- | --- |
| D-2024-0311-A | `first_drawdown` | −4% | "股价连续回调，担心继续下跌，先离场" | 2024-06-07 @1619.18（−4.44%） |
| D-2024-0108-B | `target_return` | +15% | "按事前计划离场" | 2024-02-21 @10.80（+18.03%） |
| D-2024-0520-C | `recover_after_drawdown` | 先跌 10% 再回本 | "好不容易回到成本价上方" | 2024-09-26 @205.51（+1.01%） |

推导不出时**如实标注并回退**，不会悄悄沿用构造价让报告"看起来是真的"。

## 7. 真实数据下的三条结论（与构造数据对照）

同一套算法、同一段理由，换数据源后结论不同 —— 这正是要展示的：

| 决策 | 构造数据 | 真实数据 |
| --- | --- | --- |
| A（600519.SH） | −4.05%，偏差命中 6 条 | **−4.44%**，止损线 −10% 未触及即离场 |
| B（000001.SZ） | −11.36% | **+18.03%**，触及 +15% 目标离场 |
| C（300750.SZ） | +3.79% | **+1.01%**，且**离场后该股至 2024-10-08 再涨 47%** |

真实数据下最有说服力的一条：**C 在回撤 −17.95% 后刚回本（+1.01%）就卖出，
随后该股涨到入场价的 +47%** —— 锚定成本价的代价被真实行情完整记录了下来。

另外，**同一段决策理由的可核验性也随之改变**：
构造数据里决策 A 的"预增 / 业绩"无对应字段（不可核验），
真实数据里 600519.SH 有 `revenueYoy` / `netProfitYoy`，这两项变为可核验；
反过来，决策 B 的"股息率超过 7%"在真实数据下**不可核验**（扶摇没有股息率字段），
该项置信度因此被下调。

## 8. 未做的事（如实说明）

1. **未接入 MCP 形态**：扶摇同时提供 MCP Tools，本实现只用了 REST。
2. **未接 iFinD**：题目允许的另一个数据源未使用。
3. **未做增量更新**：每次 `fetch:fuyao` 全量重取并覆盖，没有做只抓新交易日的增量逻辑。
4. **业绩预告 / 公告类事件无来源**：扶摇的资讯事件库仅在同花顺 AI 客户端内提供，
   因此决策理由里"看到业绩预增公告"这类说法的**事件依据无法核验**，只能判为不可核验。
5. **未做市况复权因子校验**：未用除复权接口交叉验证价格序列（该路由实测 404）。
