# 演示视频脚本（60–180 秒）

> 面向题目 11「可选交付物 5：60–180 秒演示视频」。
> 题目原文：*"用于展示一名用户完成核心任务，建议直接演示产品，避免以讲 PPT 代替产品体验。"*
> 因此本脚本**全程录屏 + 口播，不出现任何幻灯片**，主线是一名用户用产品完成**一次历史决策的复盘**。

- **目标时长**：约 2 分 22 秒（142 秒），落在 60–180 秒区间内，仍有删减余量。
- **旁白总量**：约 590 字，按 4.2 字/秒的清晰语速朗读（可留停顿）。
- **演示地址**：<https://investment-decision-replay.app.workbuddy.host/>
- **所有数字均为产品真实输出**，脚本里的每个值都可以在页面上复现（见第 7 节）。

---

## 1. 录制前准备（约 3 分钟，逐条打勾）

| # | 动作 | 原因 |
| --- | --- | --- |
| 1 | 浏览器窗口设为 **1440×900 或更大**，页面缩放保持 **100%** | 表格列多，缩放下文字会糊 |
| 2 | 隐藏书签栏（`Ctrl+Shift+B`），关闭无关扩展与标签页 | 画面干净，不泄露个人浏览记录 |
| 3 | **清空本地存储**：`F12` → Application → Local Storage → 删除 `replay-checklist:*` | 否则清单带着上次的勾选，看起来像"没演示" |
| 4 | 打开演示地址，确认顶部两个状态胶囊显示 **服务正常** 与 **数据源：synthetic-fixture** | 这两个是真实状态，不是装饰 |
| 5 | 关闭微信 / 邮件 / 系统通知，开启"专注模式" | 弹窗会毁掉整条素材 |
| 6 | 录屏只框选**浏览器窗口**，不录桌面 | 桌面上可能有私人文件 |
| 7 | 鼠标移动放慢，**点击前停顿约 0.5 秒**，点击后再停 1 秒 | 观众需要时间跟上你的操作 |
| 8 | 保持在默认的决策 A 页面，先不要点任何东西 | 开场镜头需要静止的画面 |

> 数据集为构造数据（`meta.source = synthetic-fixture`），标的以代号表示，
> 画面中**不含任何真实账户、持仓或隐私字段**——这一点在镜头里也会被旁白点明。

## 3. 逐字旁白稿（配音用，连续版）

> 总计约 590 字。句末 `/` 表示可停顿一拍。

这是「投资决策复盘与学习」。/ 它要解决的问题很具体：投资者只记得盈亏，却想不起当时看到了什么、为什么那样做。/ 所以第一条是边界——不给涨跌预测，不给买卖建议。/

左侧是三条历史决策，标的用代号表示，全部是构造数据。/ 真实使用时字段来自券商流水和个人笔记；账户号、流水原文这类隐私字段不会进入这里。/

先看决策 A：2024 年 3 月 11 日买入，4 月 22 日离场。/ 时间线上蓝色是决策前已可得的信息，可以用于归因；橙色是决策之后才出现的，只列示，并明确标注「禁止用于归因」。/ 往下是事实层，只做拆解，不含任何解释。/ 再往下是归因，每一条都带置信度和反事实检验。/ 行为偏差这里，它命中了六条。/

关键在这一步。/ 我把决策时点往后推 90 天：事前证据从 545 个点变成 691 个，偏差命中从 6 条降到 5 条，决策时点的估值分位从 13.6% 变成 1.4%。/ 同一个决策、换一个时点，结论就变了——所以时点必须钉死在真实决策那一刻。/

再看决策 C：结果最好，赚了 3.79%，但过程命中了「锚定成本价」——它的卖出理由是「好不容易回到成本价上方」。/ 成本价是个人记账口径，不是市场信息。/ 还有这条：2023 年报的营收同比，所属时点是去年 12 月 31 日，披露却要到 4 月 25 日，隔了 116 天。/

现在演示降级。/ 我切到「数据文件缺失」——它不会给你一份看起来正常的报告，而是直接说清楚缺了什么、影响了哪些结论。/ 缺数据时的正确答案是「无法判断」，不是「没有问题」。/

最后是沉淀：可勾选的清单、提醒，以及可以直接带入下一次决策的上下文。/ 整套输出都能导出成 JSON 或 Markdown。/

## 4. 操作顺序速查（照着点就行）

```
1. 停留在默认页（决策 A）
2. 鼠标划过合规声明条
3. 鼠标自上而下划过侧栏三条决策
4. 向下滚动：时间线 → 事实 → 归因 → 行为偏差
5. 回到顶部，下拉「决策时点闸门实验」→ 决策时点 + 90 天
6. 指出「时点闸门」行与「决策时点估值分位」
7. 点侧栏「标的C（锂电池）」，滚到行为偏差的「锚定成本价」
8. 滚到证据表最底部一行 revenueYoy:300750.SZ
9. 下拉「故障注入」→ 数据文件缺失（停 2 秒）→ 切回 无故障
10. 滚到沉没区，勾第一项清单
11. 鼠标停在「导出复盘 Markdown」
```

> 第 7 步切换到标的 C 后，报告是 **degraded** 状态，顶部会出现橙色告警条
> （2 项错误 + 1 项提示）。这是设计如此，**不要回避**——它正好是"数据有问题时不静默"的证据。
> 如果时间允许，可以在第 8 步顺手指出"已剔除的数据点"那张表（价格冲突 / 接口失败共 3 个点）。

## 5. 录制与后期建议

**录制**
- 用系统自带录屏即可（Windows：`Win+G`；macOS：`Shift+Cmd+5`），**同时单独录一路麦克风**，便于后期调音量。
- 先完整录 2–3 遍，选最顺的一遍剪；不要一句一句补录，语气会断。
- 浏览器加载有等待时不要停——继续讲，后期把等待段加速 4 倍或直接剪掉。

**后期（都可选，但前两项性价比最高）**
1. **全程字幕**：旁白全文即字幕稿，直接上。
2. **关键数字放大标注**：`545 → 691`、`6 → 5`、`13.6% → 1.4%`、`116 天` 出现时在画面角上弹出对比卡。
3. 结尾定格 3 秒，叠一行字：线上地址 + 源码仓库地址。
4. 若需要压到 60–90 秒：只保留分镜 1、3、4、7（定位 → 复盘 → 时点闸门 → 沉淀），
   把 2、5、6 压成一句带过即可。
