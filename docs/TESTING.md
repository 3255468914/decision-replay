
```
  …
全部冒烟检查通过。

✓ 已生成 dist/standalone.html（3915 KB，双击即可打开，无需服务）
```

## 2. 主链路覆盖

| 用例 | 断言要点 |
| --- | --- |
| `主链路：三条决策都能产出结构完整的报告` | 时间线非空、事实 ≥5 条、归因 ≥2 条、**偏差规则恒为 9 条（未触发也列出）**、至少有 1 项不确定、至少 1 条沉淀清单、`nextContext` 待填项 ≥3 |
| `可追溯性：每条事实都带来源；每条归因都带证据引用` | 每条 `fact.source` 非空；每条 `attribution` 有 `evidenceRefs`、合法 `confidence`、非空 `counterCheck` |
| `事实层与归因层在措辞上分离` | 事实项的 `label` 不含「因为 / 导致 / 说明 / 证明 / 由于」 |
| `偏差规则：三条决策的触发集合符合构造预期` | A 触发 6 条（含追涨、计划漂移、无证伪条件、期限不符、依据不足）；B **不**触发纪律类规则；C 必须触发锚定 |
| `结果与过程分离：B 的收益最差，但过程纪律最好` | `ret(B) < ret(A)` 且 `hits(B) < hits(A)` —— 守住"结果 ≠ 过程"的产品立场 |
| `时点闸门：事后事件被隔离，且不得出现在可归因证据里` | 决策后发布的事件不出现在 `exAnteEvidence`，但在时间线上以 `exPost` 分区展示 |
| `报告不得含 undefined / null 字符串（防止字段拼接错位）` | 遍历三条报告，断言 JSON 中无 `undefined` / `[object Object]`；每个时间线条目必须有 `title` 与 `ref` |
| `错误处理：不存在的决策 id 抛结构化错误` | 抛出 `code = DECISION_NOT_FOUND` 且返回可用 id 列表 |

> 上面那条 `undefined` 断言是**真实踩坑后的回归**：时间线改造时曾把行情数据点误当作事件传入，
> 结果渲染出「事件：undefined」。这类问题不会让程序崩溃，只会让页面悄悄出现脏内容 —— 必须有断言守住。

### 时点闸门的边界用例（本产品的核心）

| 用例 | 断言要点 |
| --- | --- |
| `边界：与决策时点完全相同的证据算作「事前可知」` | `publishedAt == decidedAt` 归入 `exAnte`；+1 秒归入 `exPost` |
| `时点缺失或不可解析的证据进入 unknown` | 缺少时间与 `"not-a-date"` 都进 `unknown`，并各产生一条 `EVIDENCE_TIME_MISSING`；**断言 unknown 不泄漏进 exAnte** |
| `决策时点不可解析时全部降级为 unknown` | 产出 `DECISION_TIME_UNPARSEABLE`（level=error），`exAnte`/`exPost` 均为空 |
| `当日收盘价（15:00）不得成为 14:20 决策的事前证据` | 事前最新收盘必须是 `2024-03-08`（决策日的前一交易日），而非 03-11 |
| `把决策时点后移会让原本「事后」的证据被纳入「事前」分区` | `asOfOverride` 之后 `exAnteCount` 增大、`exPostCount` 减小（两个方向都断言，防止搞反「事前/事后」的迁移方向） |
| `时点闸门单调性：决策时点后移，事前证据只增不减、事后证据只减不增` | 跨 `+0/+1/+7/+30/+90` 天逐档比较，并断言端点严格不等（防止断言空转） |
| `披露时滞：2023 年报的数据点在 2024-01-08 决策时不可得` | 事前证据中不得出现 `asOf=2023-12-31` 的财报点；且所有事前点的 `publishedAt ≤ decidedAt` |

## 3. 数据缺失 / 接口失败覆盖

数据集中刻意注入了 4 类异常（见 `data/meta.json` 的 `injectedAnomalies`）。

| 用例 | 断言要点 |
| --- | --- |
| `缺失值被识别为 MISSING_VALUE（warn），不会当作 0` | 报出 `MISSING_VALUE`，状态为 `degraded` |
| `同一序列同一时点的两个不同取值被识别为 CONFLICT（error）` | 报出 `CONFLICT`；**两个冲突点均被剔除，不允许任取一个** |
| `过期判定只看"决策时点可得的最新一期"` | 30 个历史点只产生 1 条 `STALE` 告警（防止噪音淹没真实问题） |
| `按序列前缀区分过期阈值：月频 PMI 不应套用日频的 7 天阈值` | 默认阈值下报 `STALE`，配置 `{'pmi:': 40}` 后不再报 |
| `数据源调用失败被标记为 SOURCE_FAILED 且不参与计算` | 带 `sourceError` 的点被剔除 |
| `完全无证据时必须 blocked，而不是输出空结论当作"正常"` | 状态 `blocked`，`banner` 含「阻断」 |
| `端到端：含异常样本的决策报告必须是 degraded` | 决策 C 同时报出 `MISSING_VALUE` / `CONFLICT` / `SOURCE_FAILED`，`removedPoints.length ≥ 3` |
| `端到端：干净数据不得被误判为降级` | 决策 A 状态为 `ok`，`banner` 为 `null` |

### HTTP 层的接口失败

| 用例 | 断言要点 |
| --- | --- |
| `故障注入：数据文件缺失 → 503，且带修复建议；绝不返回"正常"结论` | HTTP 503、`code=DATASET_MISSING`、有 `remediation`、**响应中不含 `report` 字段** |
| `故障注入：数据校验失败 → 503 且说明缺哪个字段` | `code=DATASET_INVALID` |
| `故障注入：上游超时 → 503 且说明本次不产出哪类结论` | `code=UPSTREAM_TIMEOUT`，`remediation` 含「不产出」 |
| `未知决策 id → 404，并给出可用列表` | `error.available.length === 3` |
| `路径穿越被拒绝` | `/../package.json` 返回 403 或 404 |
| `静态资源可访问` | `/`、`/app.js`、`/styles.css` 均 200 |

## 4. 扶摇真实数据源覆盖（离线，`test/fuyao.test.js`）

真实数据接入后新增的一层。**全部离线**：用构造的 API 响应做输入，不发网络请求，
在没有 Key 的环境下也能断言。分五组：

### 4.1 法定披露期限与披露日降级（7 条）

| 用例 | 断言要点 |
| --- | --- |
| `法定披露期限：一季报 4/30、半年报 8/31、三季报 10/31、年报次年 4/30` | 四个报告期的法定截止日逐一对齐 |
| `法定披露期限取当日 23:59:59，而不是当日 00:00` | **当天开盘前不能假定数据已披露** —— 保守到"当天结束" |
| `披露日在法定期限内 → 采用上游日期` | 上游可信时不得过度降级（否则会白白丢掉信息） |
| `上游披露日超出法定期限 → 判定不可信，降级到法定截止日` | 复现真实场景（600519.SH 2024Q1 上游给 2025-04-30，法定 2024-04-30） |
| `披露日早于报告期末 → 不可能成立，同样降级` | 报告期还没结束就"已披露"，逻辑上不可能 |
| `披露日缺失 → 降级而不是当作"随时可得"` | 缺失时取法定截止日，**不是**取报告期末 |
| `降级的可得时点一定不早于法定截止日 —— 绝不提前知道` | 这是核心不变式：降级只会**推迟**可得时点，永远不会提前 |

### 4.2 字段 ID 漂移与缺失（3 条）

| 用例 | 断言要点 |
| --- | --- |
| `指标 ID 匹配：精确命中优先；只有带前缀的版本时才退到后缀匹配` | 文档写 `operating_income_yoy_growth_ratio`，实际返回 `calculate_...`，两者都要能命中；两个都在时精确同名优先 |
| `指标不存在时返回 null，调用方据此不出点（不补零、不臆造）` | 缺口必须显式暴露为 `null`，绝不用 0 或累计值冒充 |
| `num() 把上游的字符串数值转成 number，空值一律 null` | 上游数值是字符串；`''` / `'abc'` / `null` 都归为 `null` |

### 4.3 估值推导（5 条）

| 用例 | 断言要点 |
| --- | --- |
| `TTM EPS：年报直接用当年 EPS` | Q4 的 TTM = 当年年报 EPS |
| `TTM EPS：季报用「上年年报 + 本年累计 − 上年同期累计」` | Q1/Q2/Q3 的拆分口径 |
| `TTM EPS：缺少上年同期数据时不出值` | 推导不成立时**不出点**，而不是用累计值冒充 TTM |
| `每股净资产：由「归母净资产 ÷ 近似股本」推导` | 股本反解自"净利润 ÷ 基本 EPS" |
| `每股净资产：输入缺失或 EPS 为 0 时返回 null` | 避免除零产生 `Infinity` |

### 4.4 时间字段映射（4 条）

| 用例 | 断言要点 |
| --- | --- |
| `财报按「可得时点」对齐，不得用未来才披露的财报算历史估值` | 估值序列的 `publishedAt` 必须来自报表披露日，不能用报告期末 |
| `日线映射：asOf 与 publishedAt 都是当日 15:00` | 收盘后才可得；价格取 2 位小数（避免前复权浮点残值） |
| `财务指标映射：publishedAt 用披露日，asOf 用报告期末，二者必须可区分` | 这是时点闸门生效的前提 |
| `报告期解析：只有季末才产出财年季度键` | 非季末月份不产出季度键 |

### 4.5 错误码、重试与卫生检查（9 条）

| 用例 | 断言要点 |
| --- | --- |
| `业务错误码映射：区分可重试与不可重试` | `4001`（限流）/ `5002`（超时）/ `5003`（不可用）可重试；`1001` / `2001` / `2003` / `3002` 不重试 |
| `未配置 API Key 时客户端直接拒绝，不留到请求阶段才报错` | 快速失败，避免无意义请求 |
| `鉴权失败不重试：只发一次请求就抛出` | **避免用错误 Key 打爆上游** |
| `非 JSON 响应（上游返回 HTML 错误页）被显式识别` | 抛 `RESPONSE_NOT_JSON`，而不是伪装成"解析失败" |
| `限流（4001）会退避重试，重试成功则正常返回` | 退避后恢复 |
| `明确声明扶摇不提供的能力清单（含股息率、不良率、PMI）` | 缺口写进 `meta.unavailableCapabilities`，对应结论报"不可核验" |
| `上游指标为 null 时不出点` | 见 4.2 |
| **`数据快照与产物中不得出现任何 API Key（题目明令禁止提交密钥）`** | 扫描 `data/real/`、`dist/`、`public/`、`docs/`，出现 `sk-` 形态串即失败 |
| **`.env 必须被 .gitignore 排除，避免密钥被误提交`** | 防止本地 Key 被误入库 |

> 最后两条是本次接入中**最值得强调**的一条防线：真实数据接入最容易犯的错误之一，
> 就是"顺手把 Key 写进快照或日志"。它们把风险挡在入库之前，而不是靠人记得别提交。

## 5. 极端与合规边界覆盖

### 合规边界

| 用例 | 断言要点 |
| --- | --- |
| `合规：输出中不得出现确定性预测 / 收益承诺 / 买卖建议 / 仓位建议` | 对三条决策的 `attribution` / `biases` / `learnings` / `headline` 全量做禁用词断言，命中即失败 |
| `合规护栏：命中即被中和，并记录 hits 供审计` | 输入 `'该股必涨，建议买入，仓位建议 8 成，预计涨到 200 元，稳赚不赔。'` → 4 类规则全部命中，且清洗后文本不含这些片段 |
| `合规护栏：清洗发生在报告返回前的最后一步` | `compliance.sanitizeHits` 存在且为数组，`disclaimer` 与常量一致 |

**护栏规则清单**（`src/guardrails.js`）：

| code | 覆盖的表达 |
| --- | --- |
| `CERTAIN_DIRECTION` | 必涨 / 必跌 / 一定会涨 / 肯定会跌 / 稳赚 / 稳赢 / 保证收益 / 百分百 / 无风险套利 |
| `PROFIT_PROMISE` | 预计涨到 N / 至少赚 N / 年化收益 N% / 包赚 |
| `DIRECT_ADVICE` | 建议买入 / 建议卖出 / 立刻买 / 马上卖 / 推荐买 / 推荐卖 / 加仓 N 成 / 梭哈 |
| `POSITION_ADVICE` | 建议仓位 N / 仓位建议 / 建议 N 成仓 |

### 极端输入

| 用例 | 断言要点 |
| --- | --- |
| `极端边界：数据点极少时不臆断` | 只有一个价格点、无平仓记录的数据集：`B-CHASE` 必须为 `triggered: null`（**未判定**，不是"未触发"）；不产出 `F-RET`；不产出 `A-3`（计划 vs 执行）；`uncertainty` 含 `U-2`（尚未平仓） |
| `边界：与决策时点完全相同的证据算作「事前可知」` | 等号边界的显式约定 |
| `决策时点不可解析时全部降级` | 见第 2 节 |

### "未判定" 与 "未触发" 的区别（设计要点）

`triggered` 有三个取值：

- `true` 已触发
- `false` 满足判定条件且确认未触发
- `null` **数据不足，无法判定**

界面上三者显示不同徽标，"未判定"不会被算作"没问题"。
测试与页面渲染都对此做了断言与区分。

## 7. 前端渲染覆盖（`npm run smoke`）

因为环境未安装无头浏览器，`scripts/smoke-ui.js` 用最小 DOM 桩替换 `document` / `localStorage` / `URL`，
再加载真实的 `public/app.js` 并打到真实的 HTTP 服务上，验证渲染流程不崩、关键内容确实被注入。

| 检查项 | 断言要点 |
| --- | --- |
| 侧栏渲染出 3 条决策 | `#decisionList` 子节点数 === 3 |
| 报告区渲染出 8 个区块 | 头部 + 时间线/证据/事实/归因/偏差/不确定/沉淀 7 张卡片 |
| 渲染结果包含产品必备内容 | 含「时间线 / 决策时点可得的证据 / 事实 / 归因 / 行为偏差 / 不确定 / 沉淀 / 下一次决策上下文」 |
| 事后信息隔离标签 | 时间线出现「事后信息 · 禁止用于归因」 |
| 事实表行数精确一致 | 事实表恰为 9 行（数量不符即失败，防止漏渲染） |
| 无脏输出 | 渲染文本不含 `undefined` / `NaN` / `[object Object]` |
| 交互：切换决策 | 触发决策 C 的 click 后，报告区完整重绘 |
| 降级时多渲染一张表 | 决策 C 出现「已剔除的数据点」表，表格数 ≥3 |
| 降级问题完整列出 | 文本含 `MISSING_VALUE` / `CONFLICT` / `SOURCE_FAILED` |
| 偏差规则 9 行全渲染 | `.bias-row` 节点数 === 9 |

## 8. 未覆盖 / 测试盲区（如实说明）

1. **前端视觉未自动化**：样式与布局没有无头浏览器断言。若继续开发，建议引入 Playwright 覆盖完整渲染与截图对比。
2. **未做并发测试**：服务端每次请求重新读盘，未测试高并发下的行为（当前定位是单机单用户）。
3. **未做上游契约的**在线**测试**：`test/fuyao.test.js` 全部离线，验证的是"**我们自己**对上游响应的解读与降级"，
   而不是"上游此刻返回的就是这个样子"。上游改字段、改披露日、改分页，离线用例不会失败。
   真实契约需要一条需要 Key 的在线冒烟（`npm run fetch:fuyao` 可手工执行，但未纳入 `npm test`，以免 CI 依赖外网与额度）。iFinD 未接入，无对应测试。
4. **推导值与真实口径未逐点比对**：PE / PB 是推导值（TTM EPS × 股价、净资产 ÷ 近似股本），
   只做了内部一致性测试，未与行情软件的公开数值逐点核对。见第 4.3 节与 `docs/DATA_SOURCE.md`。
5. **偏差规则阈值未做敏感性分析**：例如把追涨阈值从 10% 调到 8% 会改变多少条判定，尚未量化。
6. **未做长期稳定性测试**：无调度、无常驻进程，不适用。
