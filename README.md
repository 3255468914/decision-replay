# 投资决策复盘与学习 · Decision Replay

> 三道备选题中选择了 **题目 11｜投资决策复盘与学习**（24h 档）。
> 选择理由：另外两题（AI 大势研判 / 可配置监控与风险雷达）都强依赖"实时取数 + 长驻调度"，属于需要长期运行的服务；
> 本题的核心是**时点对齐与事后信息隔离**，可以用纯函数表达，因而能做到**零外部依赖、离线可复现、可自动化回归**——
> 在同样的时间里能交付一条真正跑得通且能被验证的主链路，而不是一个演示用的壳。

**在线体验（无需安装、打开即用）**：<https://investment-decision-replay.app.workbuddy.host/>

## 1. 一句话说明

把"一次历史投资决策"还原成三样东西：**决策当时能看到什么（事实）→ 结果是怎么构成的（归因）→ 我的行为里有哪些可复用的模式（偏差与清单）**。
产品的技术主张是：**先做时点闸门（point-in-time gate），再谈归因**。任何在决策之后才出现的信息，一律隔离到"事后信息"分区并打上「禁止用于归因」标签。

## 3. 产品选择：为什么是"复盘"而不是"预测"

| | 预测类产品 | 本题的复盘产品 |
| --- | --- | --- |
| 主要失败模式 | 幻觉出数字、把噪声说成信号、无法验证 | 后见之明（用事后信息解释事前决策） |
| 对策 | 需要大量真实数据与统计检验 | **时点闸门 + 事后信息隔离 + 反事实检验** |
| 可验证性 | 差（要等未来） | 好（历史数据可反复回归） |

因此本产品**刻意不做的事**：不做点位预测、不给目标价、不给仓位建议、不输出"建议买入/卖出"。
这不是能力不足的妥协，而是产品定义的一部分 —— 复盘的价值在于**让下一次决策的输入变好**，不在于多一个嘴。

## 4. AI 的角色（重要，请勿误解）

**产品运行时不含大模型调用。** 所有数字、归因拆解、偏差判定都由确定性代码产出。

理由：金融场景里最关键的是**数字可追溯**。一旦让 LLM 直接生成数字或结论，就无法保证它引用的数字真的来自原始字段。
所以本项目的分工是：

- **AI 用在研发过程**：需求拆解、领域建模、规则设计、测试用例设计、代码实现与重构（详见 `docs/AI_USAGE.md`）。
- **产品运行时是纯规则 + 模板**：任何一条输出都能对应到一个函数、一个字段、一个口径。
- **合规护栏（`src/guardrails.js`）** 是最后一道闸门，对最终输出做禁用词扫描与中和，命中记录写入 `compliance.sanitizeHits` 供审计。

> 若后续接入 LLM 做措辞润色（见第 9 节"未做事项"），必须遵守一条硬约束：
> **LLM 只能改写措辞，不得新增数字**；返回后需做数字一致性校验，命中未知数字即整体回退到模板文案。

## 5. 数据来源与口径

### 5.1 构造数据（`data/`）：演示 + 回归基线

题目统一规则明确允许"涉及用户画像/持仓时使用匿名或构造数据"。因此：

| 文件 | 内容 | 生成方式 |
| --- | --- | --- |
| `data/decisions.json` | 3 条匿名决策 + 3 条平仓记录 | 手工构造，标的名称为代号 |
| `data/market.json` | 1,979 个行情/估值/财报/宏观数据点 | `npm run gen`（确定性生成，可复现） |
| `data/events.json` | 8 条事件/资讯（含 1 条无时间戳） | 手工构造 |
| `data/meta.json` | 数据来源、口径说明、注入的异常类型 | `npm run gen` |

**行情生成方式**：先用锚点定义每个序列的形状，再在对数空间做线性插值 + 确定性抖动（mulberry32，固定种子）填充到日/周/月频。
因此 `data/market.json` 每一行都可重建，适合做回归测试。

**刻意注入的 4 类异常**（用于验证降级路径）：

| 异常 | 位置 | 期望行为 |
| --- | --- | --- |
| `MISSING_VALUE` | `revenueYoy:300750.SZ` 取值为 null | 相关结论不可计算并显式报出 |
| `CONFLICT` | `price:300750.SZ` 同一时点两个来源给出不同收盘价 | 该数据点被剔除，不做「任取一个」 |
| `SOURCE_FAILED` | `turnoverRate:300750.SZ` 带 `sourceError: HTTP 503` | 不参与归因 |
| `STALE` | `peTtm:300750.SZ` 一个 2022 年的过期快照 | 标记过期，不作强证据 |

### 5.2 两套数据源，同一套算法

产品支持切换数据源，**算法完全一致，结论差异只来自数据本身**：

| 数据源 | 位置 | 性质 | 用途 |
| --- | --- | --- | --- |
| `fixture`（默认） | `data/` | 构造数据，确定性可复现 | 演示 + **自动化回归基线**（上游会修订，真数据不适合当基线） |
| `real` | `data/real/` | **扶摇真实行情与财报快照** | 展示真实上游下的产品行为 |

默认仍是 `fixture` 是刻意的：回归测试需要逐字节可复现的输入。

### 5.3 真实数据源（扶摇）——已实现

`data/real/` 由 `npm run fetch:fuyao` 从扶摇（同花顺金融数据API）拉取后落盘：

- 2,749 个数据点 / 24 条序列；3 个标的（600519.SH、000001.SZ、300750.SZ）+ 沪深 300 指数
- **快照不含任何密钥**，可入库；页面上切换「数据源」即可对照
- PE / PB 由价格与财报**推导**（扶摇无估值接口）；
  股息率、不良率、宏观 PMI **扶摇不提供**，一律不出点，交给数据质量层报缺口

接入过程实测到 **5 处上游不一致**，其中最关键的一处：

> **扶摇返回的财报披露日（`report_date_ms`）在多个标的、多个报告期上超出 A 股法定披露期限约一年**
> （例：600519.SH 2024Q1 期末 2024-03-31，法定最晚 2024-04-30 披露，上游给 2025-04-30）。
> 同一批数据里也有正确的，所以既不能整体丢弃，也不能整体信任。
> 本次取数窗口内 36 个报告期的披露日**无一通过校验**。

披露日是时点闸门唯一的依据。若直接采信，会把当时明明已知的信息判成未知，
整个复盘的价值就没了。因此适配层按法定披露期限做合理性校验，
**不通过则降级到法定截止日**（保守：宁可晚确认，绝不提前知道），并逐条留证在
`data/real/meta.json` 的 `upstreamAnomalies` 中。

其余 4 处（字段 ID 与文档不符、文档路由 404、非 JSON 的 HTML 错误页、鉴权失败也返回 HTTP 200）
以及映射口径、推导公式、决策离场时点的推导规则，见 **[`docs/DATA_SOURCE.md`](docs/DATA_SOURCE.md)**。

### 5.4 时间字段的两层设计（本项目的关键细节）

每个数据点有两个时间，**必须分开**：

```
asOf         所属时点    "这份数据的统计期"       如 2023-12-31（年报报告期）
publishedAt  可得时点    "这份数据什么时候能看到" 如 2024-04-25（年报披露日）
```

时点闸门使用 **`publishedAt`**。如果错误地使用 `asOf`，就会把 2023 年报当成 2024 年 1 月决策时的已知信息 —— 这正是最典型的 point-in-time 错误。
`data/market.json` 中的 `nplRatio:*` 刻意设置了 **+80 天披露时滞**，测试 `披露时滞` 用例专门守住这条线。
真实数据源下这条线同样成立：财务指标点的 `asOf` 是报告期末，`publishedAt` 是披露日（或降级后的法定截止日），
两者的差值就是真实的披露时滞。

### 5.5 一个刻意的口径选择：用未复权价，不用前复权

前复权价会随**每一次分红被追溯修改** —— 同一份报告今天生成和三个月后生成，数字不一样。
对一个以"可复现"为前提的复盘产品，这是致命的。因此价格序列与成交价一律取未复权：

1. 未复权价就是当日真实成交价，与"我买在哪"口径一致；
2. 历史值不被后续除权追溯修改，报告可复现；
3. 不引入浮点残值（前复权会算出 `1560.0777699999999` 这种数）。

代价是跨除息日的持有期收益少一块分红 —— 这一点写在了 `meta.fieldCaliber` 里，没有隐去。

## 6. 解题思路与关键步骤

### 6.1 领域建模（先想清楚"复盘的输入是什么"）

一次决策复盘需要四类输入，缺一不可：

```
决策记录 decision      时点 + 动作 + 价格 + 当时的理由（原文）+ 事前预设条件(preCommit)
平仓记录 exit          时点 + 价格 + 离场理由（原文）
市场证据 market[]      每个点带 asOf / publishedAt / value / unit / source
事件     events[]      每个点带 publishedAt / impact / source
```

其中 `preCommit`（事前预设的止损线、目标、**证伪条件**）是复盘的支点：
没有它，事后只能拿收益结果反推对错，这正是后见之明的入口。

### 6.2 主链路（5 步）

```
① 时点闸门  splitByDecisionTime(market, publishedAt, decidedAt)  → exAnte / exPost / unknown
② 数据体检  checkQuality(exAnte)                                  → ok / degraded / blocked
③ 降级取数  filterUsablePoints(...)                               → 剔除冲突点与失败点，留档
④ 分层产出  buildFacts → buildAttribution → runBiasRules → buildUncertainty
⑤ 沉淀      buildLearnings → buildReminders → buildNextContext
⑥ 合规闸门  sanitizeDeep(report)                                  → 中和违规表述并记录 hits
```

**三层输出严格分开**，这是产品可信度的基础：

| 层 | 回答的问题 | 约束 |
| --- | --- | --- |
| `facts` | 发生了什么 | 只做计算与引用，**不含因果词**（有测试守住） |
| `attribution` | 结果由哪些部分构成 | 必须带 `confidence`、`confidenceReason`、`counterCheck`、`evidenceRefs` |
| `uncertainty` | 还有什么不知道 | 包含数据限制与通用口径缺口，不允许省略 |

### 6.3 时点闸门的三个设计决定

1. **边界取等号**：`publishedAt <= decidedAt` 视为事前可知。
2. **不确定就是不确定**：时间缺失或不可解析的内容进入 `unknown` 分区并上报 `warn`，**绝不默认归入事前**。
   （`data/events.json` 里刻意留了一条没有时间戳的"个人笔记"来验证这一点。）
3. **事后信息仍要展示**：隔离 ≠ 隐藏。事后信息在时间线上正常显示，但带「禁止用于归因」标签 ——
   因为用户确实需要看到"后来发生了什么"，产品要防的是**用它来解释当初**。

### 6.4 9 条行为偏差规则（每条都配反事实检验）

规则是**可解释的启发式**，不是黑箱打分。每条都必须给出证据引用，且**未触发也要输出**（只报坏消息本身也是偏差）。

| 规则 | 检测逻辑（简化） |
| --- | --- |
| `B-CHASE` 追涨 | 前 20 日涨幅 ≥ 10% 且距前 60 日高点 ≤ 3% |
| `B-DISPOSITION` 计划漂移 | 离场时既未触及止损线，也未达成目标 |
| `B-ANCHOR` 锚定成本价 | **卖出理由原文**中出现"回本 / 成本价 / 解套"等 |
| `B-INSUFFICIENT` 依据不足 | 决策时点可得的"标的层面非价格类"指标 < 2 类，或不可核验主张多于可核验主张 |
| `B-NO-INVALIDATION` 无证伪条件 | `preCommit.invalidation` 为空 |
| `B-HORIZON` 期限不符 | 实际持有天数 / 预设天数 落在 [0.5, 1.5] 之外 |
| `B-OVERCONFIDENCE` 绝对化措辞 | 理由含"一定 / 肯定 / 必然"等 |
| `B-NO-STOP` 无退出底线 | 未设 `stopLossPct` |
| `B-HINDSIGHT` 后见之明风险 | 持有期内存在决策后才出现的中高影响事件 |

每条规则都返回一个 `counterCheck`，例如 `B-CHASE` 的：

> 反例检查：动量买入在趋势延续期同样可以取得好结果，本规则只指出"入场位置偏右侧"这一形态事实，不判定该决策对错。

### 6.5 三条演示数据刻意构成一组对照

| 决策 | 结果（构造数据） | 过程命中 | 想说明什么 |
| --- | --- | --- | --- |
| A（消费） | -4.05% | 6 条 | 追涨买入 + 未触及止损就离场；且同期基准 -3.68%，**超额仅 -0.37%**——以为是"个股出问题"，其实基本跟着大盘走 |
| B（银行） | -11.36%（最差） | 1 条 | 买在下跌途中、按事前止损线离场、有证伪条件。**结果最差但过程最规矩** |
| C（锂电池） | +3.79%（最好） | 4 条 | 同期基准 -12.98%（超额 +16.77%），却以"回到成本价上方"为由卖出；同时数据处于降级状态 |

B 与 C 是专门用来打"结果导向"的：**结果差的未必决策错，结果好的未必决策对。**
测试 `结果与过程分离：B 的收益最差，但过程纪律最好` 就是在守这条产品立场。

切到**真实数据源**后，这三条会变成另一个样子（A −4.44% / B +18.03% / C +1.01%），
而最有说服力的一条是：**C 在回撤 −17.95% 后刚回本（+1.01%）就卖出，
随后该股至 2024-10-08 再涨到入场价的 +47%** —— 锚定成本价的代价被真实行情完整记录了下来。
对照表见 [`docs/DATA_SOURCE.md`](docs/DATA_SOURCE.md) 第 7 节。

### 6.6 沉淀：复盘要产出"下一次的输入"

- `learnings`：可勾选的清单（勾选状态存 `localStorage`），条目由触发的规则与数据缺口自动生成
- `reminders`：重复出现的模式、降级状态提醒
- `nextContext`：**下一次决策的上下文包**，把上一轮的证伪条件、止损线、期限、待办问题带走 → 这是"学习"真正落地的地方

## 8. 运行与验证方式

### 8.1 自动化验证

```bash
npm test          # 71 个用例：pit 6 / quality 8 / pipeline 17 / server 12 / fuyao 28
npm run smoke     # 14 项前端渲染检查（DOM 桩，无需真实浏览器）
npm run verify    # 以上两项 + 离线单文件打包，一键跑完
```

其中 `test/fuyao.test.js` 是纯离线用例（用构造的响应做输入，不发网络请求），
覆盖披露日校验与降级、字段 ID 漂移、TTM/每股净资产推导、错误码与重试策略，
以及一条**密钥不落盘**的卫生检查（扫描 `data/` `dist/` `public/` `docs/` 是否出现 `sk-` 形态的串）。

`dist/standalone.html` 是**可复现构建**：报告里的"生成时刻"统一钉在数据快照的 `generatedAt` 上
（可用 `SOURCE_DATE_EPOCH` 覆盖），因此同一份数据 + 同一份代码反复打包得到逐字节相同的文件，
`npm run build` 不会在 `git status` 里留下"只有时间戳不同"的假变更。

### 8.2 手工验证（建议按顺序走一遍，约 7 分钟）

1. **看主链路**：`npm start` → 打开 http://127.0.0.1:5173 → 默认展示决策 A 的完整复盘（构造数据集）。
2. **看时点闸门**：在"决策时点闸门实验"里把时点从"真实决策时点"改到 **+30 天**。
   观察 ① 顶部"事前/事后"点位数变化；② 时间线上原本橙色的事件变蓝；③ "决策时点可得的证据"表里出现新的一期数据。
   —— 这就是"后见之明"在数据结构上被拦住的直观演示。
3. **看数据降级**：左侧切到 **决策 C**。顶部出现黄色降级横幅，第 2 张表下方列出被剔除的冲突点与失败点，
   "不确定与数据限制"里出现 `MISSING_VALUE` / `CONFLICT` / `SOURCE_FAILED`。
4. **看接口异常**：把"故障注入"切到 **上游接口超时**。页面不产出任何结论，而是显示错误码、原因与建议，
   并明确说明"缺少数据时的正确输出是无法判断，而不是没有问题"。
5. **看合规边界**：确认页面顶部合规声明；`npm test` 中 `合规护栏` 两个用例验证禁用词被中和并留痕。
6. **看沉淀**：勾选底部清单条目 → 刷新页面，勾选状态保留；点"导出复盘 JSON / Markdown" 得到可归档文件。
7. **看数据源切换**：把「数据源」从"构造数据集"切到"真实数据（扶摇）"。
   顶栏角标变为 `fuyao`，并显示 **上游异常 36 处、字段缺口 3 项**。三条决策的**结论随数据改变、算法一字未动**：

   | 决策 | 构造数据集 | 真实数据（扶摇） |
   | --- | --- | --- |
   | A（消费 / 白酒） | −4.05% | −4.44% |
   | B（银行 / 低估值） | **−11.36%** | **+18.03%** |
   | C（新能源 / 追涨） | +3.79% | +1.01% |

   注意 B：同一套算法、同一段决策理由，仅因数据从"构造"换成"真实"，收益就从 **−11.36%（三笔中最差）**
   翻转为 **+18.03%（三笔中最好）**。而偏差判定**不跟着收益走**：真实数据下 B 依然被判为「事后合理化」
   （赚了钱也会被事后解释），并且因为真实离场使持有期从 172 天压缩到 44 天，额外触发「期限不符」。
   —— 这正是"结果 ≠ 过程"要演示的东西。
   另：股息率类依据在真实数据下被标为"不可核验"（扶摇不提供该字段）。

### 8.3 命令行验证降级

```bash
npm run analyze:fault
# 预期：打印 [数据加载失败] code=DATASET_MISSING，退出码 2，out/ 下不生成任何报告
```

## 9. 已知边界与未做事项

### 已知边界

1. **`data/` 是构造数据、`data/real/` 是真实数据**：前者不代表任何真实标的的历史表现，
   后者是扶摇的真实行情与财报。两套数据都已通过 `meta.source` 与页面角标显式标注，不会混淆。
   决策记录（买入理由、离场理由）在两套数据下**都是匿名演示样本**，非真实投资者行为。
2. **上游披露日不可信**：扶摇返回的财报披露日在多个报告期上超出法定披露期限约一年，
   适配层已降级处理并逐条留证（见 [`docs/DATA_SOURCE.md`](docs/DATA_SOURCE.md) 第 4 节）。
   降级采用法定截止日，是**保守**而非精确：真实披露日可能早于截止日，
   因此本产品的"可得时点"对财报类数据偏晚。这会让结论偏向"当时不知道"，不会偏向"提前知道"。
3. **扶摇不提供的字段一律不出点**：股息率、银行不良率、宏观 PMI 三个字段在真实数据源下缺失，
   相关结论会显式报"不可核验"。PE / PB 为**推导值**（口径见 `meta.fieldCaliber`），不是上游原始字段。
4. **用未复权价**：跨除息日的持有期收益未计入分红，因此略低于含分红的真实总收益。
   选择未复权是为了报告可复现（前复权价会被后续分红追溯修改）。
5. **交易日历简化**：构造数据集只排除周末，未剔除法定节假日与停牌日。真实数据源用的是交易所真实交易日，不受此限制。
6. **归因口径是算术差**：`超额收益 = 个股收益 - 基准收益`，未做行业中性化与风险因子回归。产品文案里明确写了它"不等同于选股能力"。
7. **偏差规则是启发式**：阈值（20 日 / 10% / 3% / 2 类指标）是经验值，不是统计拟合结果；每条规则都因此配了反例检查，并允许"未判定"状态。
8. **`unknown` 分区不参与归因**：缺时间戳的信息会被隔离，代价是信息利用率下降 —— 这是刻意选择的保守策略。
9. **API 响应按序列裁剪**：`exAnteEvidence` / `exPostEvidence` 每个序列只返回"可得时间"最后 40 期（`evidenceTailPerSeries`），
   时间线每个序列只放最近 3 期。原因是前端不需要上千个历史点，全量返回会让载荷膨胀到 MB 级。
   **参与计算的始终是数据**，真实总数见 `pit.exAnteCount`；需要全量时调用 `buildReport(ds, id, { maxPointsPerSeries: Infinity })`。
10. **单机单用户**：无鉴权、无持久化（清单状态在浏览器本地）。默认绑定 `0.0.0.0` 以便云托管，纯本机使用建议设 `HOST=127.0.0.1`。

### 未做事项

1. **未接入 iFinD 数据源**：扶摇已接入（见第 5.3 节与 [`docs/DATA_SOURCE.md`](docs/DATA_SOURCE.md)），
   iFinD 仍只预留了配置位（`.env.example` 的 `IFIND_MCP_*`），未实现适配。
2. **未接入 LLM 润色**：产品运行时不调用大模型（见第 4 节）。若接入，需配套实现"数字一致性校验 + 失败回退"。
3. **未做组合层面复盘**：目前是单笔决策视角，没有组合敞口、同期其他决策的机会成本、相关性分析。
4. **演示视频已录制、尚未上传**（可选项）：90 秒成片已录好，上传到 GitHub Release 后把链接填进第 2 节
   「演示视频」即可 —— 上传步骤见 [`docs/PUBLISH.md`](docs/PUBLISH.md) 第 6 节，配套脚本与分镜见 `docs/DEMO_SCRIPT.md`。
5. **未做多决策横向对比与统计**：例如"我在追涨类买入上的平均表现"。数据量（3 条）也不支持。
6. **未做移动端适配优化**：布局在窄屏可降级为单列，但控件未做触屏优化。
7. **未做多环境部署 / CI**：已部署到公网（<https://investment-decision-replay.app.workbuddy.host/>，零依赖 Node 单端口服务），
   但未配置 CI/CD 与多环境（dev / staging / prod）。重新发布即覆盖线上内容。
